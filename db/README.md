# Database scripts

PostgreSQL 16+ (tested against 16/17). Everything the Angular site used to keep in
TypeScript data files now lives here.

```
db/postgresql/
  00_create_database.sql   one-time bootstrap: role + database (run as superuser)
  V1__schema.sql           all tables, indexes and constraints
  V2__seed_content.sql     catalogue migrated from the old index.html
  V3__seed_ott.sql         roles and subscription plans
```

## Run it

```bash
# 1. database + role (as a superuser)
psql -U postgres -f db/postgresql/00_create_database.sql

# 2. schema + data (as the addabaaz user)
PGPASSWORD=addabaaz_dev_password psql -h localhost -U addabaaz -d addabaaz -f db/postgresql/V1__schema.sql
PGPASSWORD=addabaaz_dev_password psql -h localhost -U addabaaz -d addabaaz -f db/postgresql/V2__seed_content.sql
PGPASSWORD=addabaaz_dev_password psql -h localhost -U addabaaz -d addabaaz -f db/postgresql/V3__seed_ott.sql
```

The seed files are idempotent — re-running `V2`/`V3` upserts on natural keys
(`show.key`, `poster.file_name`, `plan.code`), so it's safe after adding content by hand.

## Conventions

- Every table has a `uuid` primary key generated by `gen_random_uuid()`.
- Content tables reference the old string ids (`v35`, `POSTER (1).png`) through
  `external_id` / `file_name` so the seed stays idempotent.
- `refresh_token` and `captcha_challenge` store **hashes**, never the raw value.
- `playback_progress` / `watch_history` carry either an `episode_id` or a `promo_id`
  (enforced by `ck_progress_target`).
- `watchlist`, `playback_progress` and `watch_history` require a `profile_id` — every
  account gets a default profile at registration.

## Flyway

The backend reads these same files as migrations
(`spring.flyway.locations=classpath:db/postgresql`, see `backend/pom.xml`, which maps
`db/postgresql` into the classpath). Set `spring.flyway.enabled=true` (default) and the
schema is created/updated on boot; set it to `false` to manage the database by hand.
